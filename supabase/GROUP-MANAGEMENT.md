# เปลี่ยนชื่อและลบกลุ่ม

## ขั้นตอนใน Supabase

1. สำรองข้อมูลก่อนทดสอบการลบจริง และใช้กลุ่มทดสอบที่ยอมลบทิ้งได้
2. ฐานข้อมูลต้องมี schema เดิมจาก `setup-all.sql` พร้อมตารางแชท `public.messages` ที่มี `group_id` และ `file_path` และ bucket เดิม `chat-images` ไม่ต้องรัน setup-all ซ้ำถ้าใช้งานกลุ่มได้อยู่แล้ว
3. เปิด SQL Editor ในโปรเจกต์ Supabase ที่แอปเชื่อมต่อ แล้วรัน **group-management.sql ทั้งไฟล์** ด้วยสิทธิ์ผู้ดูแล การแก้ทั้งหมดอยู่ใน transaction และรันซ้ำได้ ไม่ต้องใส่ key เพิ่มในแอป
4. ถ้ารันไม่ผ่านเพราะไม่มี messages/คอลัมน์/Storage ให้ตรวจ schema แชทจริงก่อน ไม่สร้างตารางทับของเดิม หากมี policy SELECT แบบ restrictive ใน storage.objects ต้องอนุญาตผู้สร้างอ่าน metadata ของไฟล์กลุ่มที่กำลังลบด้วย (การลบผ่าน Storage API ต้องมี SELECT และ DELETE)
5. เปิดแอปด้วย `npm start` เข้าหน้า Group Detail ของกลุ่มที่สร้างเอง จะเห็น “เปลี่ยนชื่อกลุ่ม” และ “ลบกลุ่ม”

SQL เพิ่มเพียงคอลัมน์ `groups.deletion_pending` ใช้ตารางเดิม เพิ่ม RPC ตรวจ `auth.uid()` เทียบกับ `created_by` และสิทธิ์ลบไฟล์เฉพาะผู้สร้างของกลุ่มที่รอลบ ไม่ใช้ service-role key ในแอป ไม่ลบ storage.objects ด้วย SQL

## การทำงานและการลองใหม่

- เปลี่ยนชื่อรับ 1–60 ตัวอักษร และอัปเดต state กลุ่มร่วมของทุกหน้าในแอปที่เปิดอยู่ บัญชีหรืออุปกรณ์อื่นเห็นชื่อใหม่เมื่อโหลดข้อมูลใหม่
- ลบเป็นสองช่วง: ตั้งสถานะรอลบและกันข้อมูล/ไฟล์ใหม่ จากนั้นลบไฟล์ผ่าน Storage API ทีละไม่เกิน 100 ไฟล์ รวมไฟล์กำพร้าใน prefix `<group_id>/` จนไม่เหลือ แล้วตรวจซ้ำฝั่ง SQL และลบข้อความ งาน สมาชิกภาพ และกลุ่มใน transaction เดียว
- ถ้าเครือข่ายหรือสิทธิ์ Storage ผิดพลาด จะไม่ลบข้อมูลกลุ่มขั้นสุดท้าย ไฟล์ที่ลบสำเร็จแล้วกู้คืนไม่ได้ กลุ่มจะยังรอลบ ให้ผู้สร้างเปิด “ลบกลุ่ม” แล้วกด “ยืนยันลบกลุ่ม / ลองใหม่” หลังแก้ปัญหา สามารถปิดแอปแล้วกลับมาลองใหม่ได้ ไม่ควรยกเลิกสถานะรอลบเอง
- ถ้าไฟล์ใน messages มี path นอก prefix ของกลุ่ม SQL จะปฏิเสธก่อนเริ่มลบ ให้ผู้ดูแลตรวจข้อมูลและย้ายไฟล์อย่างถูกต้องก่อน ไม่ลบไฟล์ข้ามกลุ่ม
- ปุ่มยกเลิกปิดหน้าต่างก่อนเริ่มทำงาน หากเริ่มลบแล้วและล้มเหลว การปิดหน้าต่างไม่ได้คืนไฟล์ที่ลบไปหรือยกเลิกสถานะรอลบ
- งานส่วนตัว (`group_id is null`) กลุ่มอื่น และ profiles/auth users ไม่ถูกลบ
- SQL ไม่ได้ยกเลิกลิงก์ไฟล์ที่ผู้ใช้ดาวน์โหลดไว้ก่อนหน้า และการเปลี่ยนชื่อไม่ได้เพิ่ม realtime sync ข้ามอุปกรณ์

## ตรวจรับบน Supabase จริง

ใช้ผู้สร้าง A สมาชิก B และคนนอก C: A เปลี่ยนชื่อได้และชื่อว่างถูกปฏิเสธ; B/C ไม่มีปุ่มและเรียก RPC เปลี่ยนชื่อ/เริ่มลบ/จบลบไม่ได้; anon เรียก RPC ไม่ได้ ทดสอบกลุ่มที่มีงาน ข้อความ ไฟล์แนบ และไฟล์กำพร้าในโฟลเดอร์เดียวกัน ตรวจว่างานส่วนตัว กลุ่มอื่น และบัญชียังอยู่หลังลบ

ลองปิดเครือข่ายระหว่างลบไฟล์แล้วลองใหม่ ตรวจว่าไม่รายงานสำเร็จเมื่อไฟล์ยังเหลือ และเพิ่มข้อความ/งาน/ไฟล์ระหว่างรอลบไม่ได้ ตรวจ Storage browser ว่า prefix กลุ่มว่างจริงหลังลบสำเร็จ การทดสอบอัตโนมัติใช้ PostgreSQL จำลองผ่าน PGlite และจำลอง Storage API; ยังต้องทดสอบบริการ Storage จริงและหน้าจอบนอุปกรณ์หลังรัน SQL

คำสั่งตรวจในโปรเจกต์: `npm run lint`, `npm run typecheck`, `npm test`.
