# Donee — งานส่วนตัว กลุ่ม และรหัสเชิญเชื่อม Supabase

## สมาชิกในทีม

- นางสาวณัฐณิชา ประทีปพงศ์
- นางสาวปารินัทธ์ นนทะเสน
- นางสาวปัญจรัตน์ สำภา
- นางสาวณัฐธยากรณ์ แสงสว่าง

## การตั้งค่าและเริ่มใช้งาน

สำหรับโปรเจกต์ Supabase ที่ตั้งค่าและใช้งานได้แล้ว ไม่ต้องรัน SQL ซ้ำเพื่อ push GitHub หรือ deploy เว็บใหม่

สำหรับการติดตั้งบนฐานข้อมูลใหม่:

1. เตรียมตารางตามโครงสร้างในโปรเจกต์ ได้แก่ `profiles`, `groups`, `group_members`, `tasks` และ `messages` พร้อม bucket `chat-images` และ Policies ของแชท/ไฟล์แนบ สคริปต์ด้านล่างไม่ได้สร้าง schema แชททั้งหมดให้อัตโนมัติ
2. รัน `supabase/setup-all.sql` ใน Supabase SQL Editor เพื่อกำหนดสิทธิ์งานส่วนตัวและ RPC ของกลุ่ม ไม่ต้องรัน `setup-tasks.sql` และ `setup-groups.sql` แยกอีก
3. รัน `supabase/group-management.sql` เพิ่ม เพื่อรองรับการเปลี่ยนชื่อ ลบกลุ่ม และควบคุมการลบไฟล์แนบ ดูรายละเอียดใน [คู่มือจัดการกลุ่ม](supabase/GROUP-MANAGEMENT.md)
   - สคริปต์รันซ้ำได้ แต่ควรตรวจผลลัพธ์และสำรองข้อมูลก่อนเปลี่ยนการตั้งค่าฐานข้อมูล
   - ถ้าพบข้อมูลสมาชิกหรือรหัสเชิญซ้ำ ให้ตรวจแก้เฉพาะรายการที่ซ้ำ ไม่ลบทั้งตาราง
4. ตั้งค่า `EXPO_PUBLIC_SUPABASE_URL` และ `EXPO_PUBLIC_SUPABASE_KEY` ใน `.env.local` โดยใช้ Project URL และ Publishable key ของโปรเจกต์ ห้ามใส่ Secret key หรือ service-role key และห้าม commit `.env.local`
5. รัน `npm install` แล้วเริ่มเว็บด้วย `npm run web` หรือเริ่มทดสอบบนโทรศัพท์ผ่าน Expo Go ด้วย `npm start`
6. สมัครสมาชิก ยืนยันอีเมลตามการตั้งค่า Supabase และเข้าสู่ระบบด้วยอีเมล/รหัสผ่าน

สำหรับ Vercel กำหนดค่าการเชื่อมต่อชื่อเดียวกันใน Environment Variables การ push GitHub ไม่ได้รัน SQL บน Supabase ให้อัตโนมัติ

## ทำอะไรได้แล้วในโค้ด

- Email/Password signup/login/logout และกู้ session
- โหลด เพิ่ม แก้ไข ติ๊กเสร็จ และลบงานส่วนตัวจาก Supabase
- สร้างกลุ่มในฐานข้อมูล พร้อมเพิ่มผู้สร้างเป็นสมาชิกในรายการเดียวกัน (transaction)
- สร้างรหัสเชิญ 12 ตัวบนฐานข้อมูล ไม่ซ้ำกับกลุ่มอื่น ไม่ใช้รหัสตัวอย่าง CREATE อีกแล้ว
- ดู/คัดลอกรหัสกลุ่มที่ตนเป็นสมาชิก แล้วให้บัญชีอื่นกรอกเข้าร่วม
- เข้าร่วมผ่านแท็บ Join Group โดยกรอกรหัสในหน้า Groups เข้าร่วมซ้ำไม่เพิ่มสมาชิกซ้ำและแจ้งเฉพาะในฟอร์ม
- ผู้สร้างกลุ่มเปลี่ยนชื่อและลบกลุ่มได้ โดยตรวจสิทธิ์ผ่าน RPC ใน Supabase
- ลบไฟล์แนบผ่าน Storage API ก่อนลบข้อมูลกลุ่ม หากลบไม่ครบ กลุ่มจะรอลบและให้ผู้สร้างลองใหม่
- แชทกลุ่มพร้อมแนบรูปภาพและเอกสาร
- โหลดรายชื่อสมาชิกจาก UUID จริง แม้ชื่อสมาชิกเหมือนกันก็แยกคนได้
- สมาชิกเพิ่ม แก้ไข ติ๊กเสร็จ และลบงานของกลุ่มร่วมกันได้
- สุ่มงานที่ยังไม่เสร็จให้สมาชิกจริง และบันทึก assigned_to เป็น UUID
- บันทึกผลมอบหมายทั้งชุดพร้อมกัน ถ้ามีงานผิดกลุ่ม สมาชิกไม่ถูกต้อง หรืองานเสร็จไปแล้ว จะไม่บันทึกบางส่วน
- งานกลุ่มที่ตนรับผิดชอบแสดงใน My Tasks และ Calendar ด้วย
- รีเฟรชข้อมูลเบื้องหลังทุก 20 วินาทีเมื่อแอปทำงานและไม่ได้เปิดฟอร์มหรือบันทึกข้อมูล รวมถึงเมื่อกลับเข้าแอป โดยคงข้อมูลเดิมระหว่างโหลด และกดโหลดใหม่เองได้ ยังไม่ได้ใช้ Supabase Realtime subscriptions
- ข้อความแจ้งผลแยกตามหน้าและกลุ่ม ไม่ติดตามไปแสดงในแท็บอื่น
- Login และ Sign Up สลับฟอร์มภายในหน้าเดียว
- ปุ่ม Notifications แสดงงานที่ยังไม่เสร็จซึ่งถึงกำหนดวันนี้หรือเลยกำหนดวันแล้ว เมื่อเปิดดูภายในแอป
- Groups เป็นกลุ่มส่วนตัว จึงไม่มี Explore รายชื่อกลุ่ม/รหัสเชิญของคนอื่น

## วิธีทดสอบด้วยสองบัญชี

1. บัญชี A Login → Groups → Create Group
2. เปิดกลุ่ม → เชิญเพื่อน → คัดลอกรหัส
3. เปิดอีกเบราว์เซอร์/หน้าต่างส่วนตัว/อีกเครื่อง → Login บัญชี B
4. Groups → Join Group → วางรหัสของ A → Join Group
5. A กดโหลดใหม่ หรือรอรอบโหลด → ต้องเห็น B ในสมาชิก
6. เพิ่ม Group Task จากบัญชี A → บัญชี B โหลดใหม่ → ต้องเห็นงานเดียวกัน
7. เลือกงาน/สมาชิก → Randomize → View in Group (เป็นปุ่มยืนยันบันทึกผล)
8. ตรวจ Supabase ตาราง tasks: group_id เป็นรหัสกลุ่ม และ assigned_to เป็น UUID ของผู้รับผิดชอบ
9. Reload เว็บ/ออกแล้วเข้าใหม่ → งาน กลุ่ม สมาชิก และผู้รับผิดชอบต้องยังอยู่

## ข้อจำกัดปัจจุบัน

- ปุ่ม Continue with Google ยังไม่ได้เชื่อมต่อ Google Sign-In
- ยังไม่มี Push Notifications หรือการซิงก์กับ Google Calendar
- ไม่มีการเก็บประวัติสุ่มแต่ละรอบ เก็บเฉพาะผู้รับผิดชอบปัจจุบันใน tasks
- ยังไม่มีระบบออกจากกลุ่มหรือแก้ไข/ลบข้อความแชทเป็นรายข้อความ
- ไม่มีระบบบทบาทเพิ่มเติม แต่แยกสิทธิ์ผู้สร้างสำหรับเปลี่ยนชื่อและลบกลุ่มแล้ว

## ไฟล์ที่แก้

- src/app/ และ src/state/DoneeProvider.jsx: ใช้ Expo Router แยกหน้าจอและใช้ข้อมูลจริง ปุ่มสร้าง/เข้าร่วม/เพิ่มงาน/สุ่มเรียกฐานข้อมูล พร้อมสถานะกำลังบันทึกและข้อความ error
- lib/groups.js: RPC สร้างกลุ่ม เข้าร่วม โหลดสมาชิก เปลี่ยนชื่อ ลบกลุ่มพร้อมไฟล์แนบ และบันทึกการมอบหมาย
- lib/tasks.js: รองรับทั้งงานส่วนตัวผ่านตาราง และงานกลุ่มผ่าน RPC
- supabase/setup-groups.sql: functions และสิทธิ์ข้อมูลกลุ่ม
- supabase/setup-all.sql: รวมการตั้งค่างานส่วนตัวและกลุ่มพื้นฐาน
- supabase/group-management.sql: RPC และสิทธิ์เปลี่ยนชื่อ/ลบกลุ่ม รวม Trigger และ Storage Policies สำหรับลบไฟล์แนบ
- supabase/GROUP-MANAGEMENT.md: คู่มือตั้งค่าและทดสอบการจัดการกลุ่ม
- scripts/groups-db.test.mjs: ทดสอบ SQL จริงบน PostgreSQL ในหน่วยความจำ (PGlite)
- scripts/groups-client.test.mjs / tasks.test.mjs: ทดสอบคำสั่ง client และการแปลงข้อมูล
- package.json / package-lock.json: เพิ่มตัวทดสอบฐานข้อมูลเป็น dev dependency และคำสั่ง npm test

## การเข้าถึงข้อมูล

- คนนอกกลุ่มอ่านกลุ่ม รหัสเชิญ สมาชิก หรืองานกลุ่มไม่ได้
- รายชื่อสมาชิกในกลุ่มส่งเฉพาะชื่อและ UUID ไม่ส่งอีเมลของคนอื่น
- ใช้ RPC สำหรับสร้าง/เข้าร่วมกลุ่มและจัดการงานกลุ่ม เพื่อให้ server ตรวจสิทธิ์เอง
- เฉพาะผู้สร้างเปลี่ยนชื่อและลบกลุ่มได้ การลบครอบคลุมข้อมูลการเป็นสมาชิก งานกลุ่ม ข้อความ และไฟล์แนบ โดยไม่ลบบัญชีผู้ใช้ งานส่วนตัว หรือกลุ่มอื่น
- งานส่วนตัวเห็นและแก้ได้เฉพาะเจ้าของ
- สมาชิกทุกคนในกลุ่มเพิ่ม/แก้/ติ๊ก/ลบงานกลุ่ม และสุ่มมอบหมายได้ ตามพฤติกรรมงานกลุ่มที่ใช้ร่วมกัน
- SQL เปิด RLS และเพิ่ม restrictive guards ไม่ได้ปิด RLS หรือเปิดให้ anonymous เขียนข้อมูล

## การตรวจสอบ

```bash
npm run lint
npm run typecheck
npm test
```

ผลตรวจล่าสุดผ่าน lint, typecheck และเทสต์ 25 รายการ ครอบคลุมงานส่วนตัว กลุ่ม รหัสเชิญ การมอบหมายงาน สิทธิ์ผู้สร้างในการเปลี่ยนชื่อ/ลบกลุ่ม การลบไฟล์บางส่วนและลองใหม่ รวมถึงการคงข้อมูลของกลุ่มอื่นและงานส่วนตัว

การทดสอบอัตโนมัติใช้ PostgreSQL ในหน่วยความจำผ่าน PGlite และจำลองคำสั่ง client/Storage API ไม่ใช่การทดสอบบริการ Storage จริงทุกกรณี ควรทดสอบด้วยสองบัญชีและกลุ่มทดลองบน Supabase จริง รวมถึงตรวจเว็บหลัง deploy
